# 数据卡

## 用途

该数据集用于验证版本、适用范围、规则冲突和拒答感知的 RAG。所有企业名称、制度内容和数值均为虚构，不代表真实公司政策，也不能用于人事、法律、财务或安全决策。

## 规模

- 29 份 Markdown 制度文件
- 10 个 policy family
- 83 个标题感知 chunk
- 108 条查询
- 开发集 54 条，测试集 54 条
- 每个集合均有 48 条可回答问题和 6 条不可回答/冲突问题

制度领域包括休假、差旅、远程办公、数据保留、生产事件、学习预算、费用报销、权限生命周期、采购审批和育儿福利。

## Hard negatives

数据有意包含：

- 内容高度相似但有效期不同的 2024/2025/2026 版本。
- 全球规则和中国/英国地区补充条款。
- 正式员工、实习生、外包人员和受限岗位差异。
- 同一个 rule key 在两份同级有效文件中出现不同值。
- 中英文混合表达、缩写和口语别名。
- 领域外问题、缺失时间、缺失地区和语料未覆盖的细粒度问题。

## 标注字段

每个 JSONL 样本包含：

| 字段 | 含义 |
|---|---|
| `query_id` | 稳定问题 ID |
| `split` | `dev` 或 `test` |
| `query` | 用户问题 |
| `as_of` | 查询所对应日期 |
| `region` | 地区范围 |
| `employee_type` | 员工类型 |
| `answerable` | 当前语料和条件下是否应回答 |
| `relevant_doc_ids` | 相关制度 ID |
| `relevant_rule_key` | 相关结构化规则 |
| `expected_value` | 期望规则值 |
| `tags` | temporal、scope、alias、cross_lingual 等切片 |

相关 chunk 必须同时满足文档 ID 和 rule key。只找到正确文档但命中错误章节不会计为相关结果。

## 划分

每个可回答规则编写两个问法：直接问法进入开发集，改写或中英文混合问法进入测试集。不可回答样本在两个集合中均匀划分。开发集只用于选择拒答阈值，测试集用于最终报告。

这个划分适合验证同域改写和阈值泛化，不等于跨领域泛化测试。后续应增加来源模板完全不同的外部语料，并确保问题作者看不到目标 chunk 的原句。

## 指标

- `Hit@1/3/5`
- `MRR@10`
- `nDCG@10`
- `stale_or_wrong_scope@1`
- `rule_value_accuracy`
- `answerability_accuracy`
- 按 temporal、scope、alias、cross_lingual 等 tag 切片的 Hit@3

`stale_or_wrong_scope@1` 单独统计 Top-1 是否违反日期、地区或人群约束。它能发现“语义相关但业务不适用”的结果，这类错误只看普通 relevance 指标容易被忽略。

## 生成与修改

执行 `python scripts/generate_sample_data.py` 可以重新生成受控样例。脚本若发现 `data/corpus` 中存在非样例 Markdown 文件会拒绝覆盖，以保护用户接入的真实数据。

新增真实语料后，应单独建立新的评测集和输出目录。不要把样例结果当作真实语料效果。

## 已知局限

- 文档规模较小，不能代表大规模 ANN 检索的召回和延迟。
- 结构化 rule 由构造过程直接提供；真实项目需要离线抽取、人工校验和版本治理。
- 问题覆盖的语言风格有限。
- 不可回答样本数量较少，生产阈值需要更多真实日志校准。
- 当前只标注一个主要相关制度；现实问题可能需要多跳聚合多个章节。
